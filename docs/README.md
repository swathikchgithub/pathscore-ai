# Documentation

| Document | What it answers |
|---|---|
| [PRD.md](PRD.md) | What is this, who's it for, what does it need to do (functional/non-functional requirements) |
| [TDD.md](TDD.md) | How is it actually built — data model, config schema, API contract, algorithms + complexity, testing strategy, known limitations |
| [ARCHITECTURE.md](ARCHITECTURE.md) | System diagrams — context, components, data flow, request/job sequences, target deployment view |
| [adr/](adr/README.md) | Why each major decision, what else was considered, and why it was rejected |
| [DEPLOYMENT.md](DEPLOYMENT.md) | Current state (local only) and the recommended, not-yet-executed path to a real deployment |
| [CODE_WALKTHROUGH.md](CODE_WALKTHROUGH.md) | A presenter's script for walking someone through this codebase live, in order |

Start with the PRD if you're asking "what is this system for." Start with
ARCHITECTURE if you're asking "how do the pieces fit together." Start with an
ADR if you're asking "why this instead of the obvious alternative." Start
with CODE_WALKTHROUGH if you need to present this codebase to someone else.
